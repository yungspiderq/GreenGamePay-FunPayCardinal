# GreenGamePay для FunPay Cardinal

Плагин для **[sidor0912/FunPayCardinal](https://github.com/sidor0912/FunPayCardinal)**: связывает оплаченные заказы FunPay с API **[GreenGamePay / пополнистим.рф](https://greengamepay.readme.io/reference/информация)**.

Устанавливается одним файлом **[greengamepay.py](greengamepay.py)**. Откройте `/ggp` в Telegram-боте Cardinal: появится **меню с кнопками**, статусом и переключателями. Python 3.10+. Зависимости `requests` и `pyTelegramBotAPI` уже входят в Cardinal.

## Новое в 1.3.1: новые лоты без перезапуска

После создания и публикации лота на FunPay откройте **`/ggp` → 📦 Мои лоты** — список автоматически загрузится заново. Если список уже открыт, нажмите **🔄 Обновить лоты с FunPay**. Перезапускать Cardinal или переустанавливать плагин не нужно.

Перед настройкой и сохранением привязки плагин дополнительно проверяет лот на FunPay. Новые лоты добавляются в профиль Cardinal, чтобы события их заказов корректно распознавались. История неактивных лотов Cardinal не удаляется. При сетевой ошибке остаётся прежний список с предупреждением; старая привязка не перезаписывается.

Профиль FunPay показывает опубликованные активные лоты. Выключенный или ещё не опубликованный лот может отсутствовать в списке. Сохранённые привязки отсутствующих лотов остаются видны с пометкой «Не виден в профиле FunPay».

## Снятие лотов при низком балансе

Откройте **`/ggp` → 🛡 Отключение лотов при низком балансе**.

1. Нажмите **💵 Задать порог USD** для Steam и подарков Steam. Например, `10`: при остатке **10 USD или меньше** связанные лоты будут сняты с продажи.
2. При необходимости задайте **💎 порог TON** для Stars и Premium. Например, `2,5`. Не заданный порог означает, что соответствующая валюта не контролируется.
3. Нажмите **🟢 Включить контроль**, затем **🔍 Проверить баланс сейчас**. В **реальном режиме** лоты действительно отключаются на FunPay. В тестовом режиме показывается только уведомление, лоты не меняются.

Это пороги **баланса GreenGamePay**, а не суммы пополнения покупателя. Даже если ваш лот пополняет Steam на 100 RUB, порог поставщика для него задаётся в **USD**. Порог `0` срабатывает только при нулевом остатке.

Проверки выполняются примерно раз в минуту, после покупки, включения контроля и изменения порога. Сетевые задержки и занятая очередь могут увеличить интервал. Для защиты нужно держать Cardinal запущенным и плагин включённым. Переключатель автопокупки можно выключить: контроль баланса работает отдельно.

Контроль охватывает **только настроенные в плагине лоты**, включая лоты на паузе. Он меняет активность лота на FunPay; цену, название и описание не меняет. Уже оплаченные заказы продолжают обрабатываться. Контроль не резервирует деньги и не отменяет заказы, успевшие поступить между проверками.

При снятии приходит уведомление в Telegram. В журнале сохраняется запрет на включение: штатное автовосстановление Cardinal через `account.save_lot` не возвращает эти лоты обратно, в том числе после перезапуска. Прямые изменения на сайте FunPay и через другие экземпляры бота не перехватываются; очередная успешная проверка низкого баланса снова снимет лот.

**После пополнения** нажмите **▶️ Вернуть лоты после пополнения** и подтвердите. Плагин заново проверит баланс: он должен быть **выше порога**. Включаются только лоты, которые контроль сам пытался снять; заранее выключенные лоты остаются выключенными. Самостоятельно после пополнения плагин лоты не включает.

Ошибка API или неожиданный ответ не превращаются в нулевой баланс: новые лоты по такой ошибке не снимаются, существующие запреты сохраняются. Неудачные операции FunPay отмечаются уведомлением и проверяются повторно. Повторяющиеся ошибки не присылаются каждую минуту.

Выключение контроля, удаление порога, отвязка лота, отключение самого плагина или переход в тестовый режим прекращают соответствующий запрет включения. Сам GreenGamePay-плагин при этом не включает лоты, но штатное автовосстановление Cardinal снова сможет это сделать. История снятия остаётся в базе.

**По умолчанию контроль выключен**, пороги не заданы. При обновлении старые настройки продаж не меняются.

## Другие возможности

- **🧮 Проверить расчёт** в карточке лота: введите число купленных штук и увидите, сколько получит покупатель. Проверяется тот же лимит объёма, что при реальной обработке. API поставщика не вызывается.
- **🩺 Проверка готовности**: режим сообщений Cardinal, подключённые лоты, совпадения названий и конфликты автовыдачи. Проверяет локальные настройки по текущему профилю; авторизацию и баланс проверяйте отдельной кнопкой.
- **⏸ Пауза для новых заказов** отдельного лота без удаления настройки. Уже принятые заказы продолжают обрабатываться. Возобновление не выполняет закупку пропущенных заказов задним числом.
- **📊 Сводка**: все записи журнала, новые за последние 24 часа, ожидание покупателя, проблемы, подтверждённые оплаты, тесты и ручное завершение.
- **🔎 Найти по номеру** в списке заказов — поиск по всему журналу, включая старые заказы.
- Подписи настроек объясняют сумму, которую получает покупатель. Например: **100 RUB за 1 штуку → 200 RUB за 2 штуки**. Цена продажи на FunPay задаётся отдельно.

## Управление кнопками

- **🔑 Подключение** — бот по очереди запросит логин и пароль, затем можно проверить баланс.
- **📦 Мои лоты** — выберите лот кнопкой и пройдите мастер: товар → объём → лимит → сохранение. JSON вводить не нужно.
- **🟢 Включить / 🔴 Остановить автопокупку** — переключатель обработки заказов.
- **✅ 🧪 Тестовый режим** — тест без списаний. Переход к реальным покупкам подтверждается отдельной кнопкой.
- **📋 Заказы** — статусы по-русски и подходящие действия для каждого заказа.
- **💰 Баланс**, **📚 Каталог**, **❓ Помощь**, **🔄 Обновить меню** и **⬅️ Назад к плагину**.

Меню обновляется в том же сообщении. Старые кнопки не меняют настройки. Незавершённый мастер можно отменить; существующая привязка лота сохранится. На ввод каждого шага даётся 15 минут.

## Что умеет

| Вид лота | Режим | Что отправляется поставщику |
| --- | --- | --- |
| Пополнение Steam | `steam` | Логин, сумма в USD; возможен пересчёт из RUB/KZT/UAH |
| Telegram Stars | `stars` | Подтверждённый @username и количество Stars |
| Telegram Premium | `premium` | @username и 3, 6 или 12 месяцев |
| Подарок Steam | `gift` | Ссылка приглашения, SUB_ID игры и регион |

Плагин проверяет оплаченный заказ непосредственно через FunPay, запрашивает получателя и отдельное подтверждение, хранит журнал SQLite и не повторяет покупку после неопределённого результата. Есть баланс USD/TON, просмотр каталога, привязки лотов, лимиты и тестовый режим без обращений к API поставщика.

**Статус релиза:** проверен автоматическими тестами с подменой внешних API и загрузчиком Cardinal. Реальные покупки, доставка товаров и работа с вашим аккаунтом GreenGamePay не проверялись. Для Premium в публичной OpenAPI-схеме отсутствует пример ответа котировки: плагин ожидает числовое поле `ton` и останавливает покупку, если его нет. Совместимость этого ответа нужно проверить на аккаунте перед продажами.

## Установка

1. Скачайте `greengamepay.py` из [последнего релиза](https://github.com/yungspiderq/GreenGamePay-FunPayCardinal/releases/latest).
2. В Telegram-боте Cardinal: `/menu` → **Плагины** → **Добавить плагин**, отправьте файл. Либо поместите его в папку `plugins/` Cardinal.
3. Перезапустите Cardinal. Откройте `/ggp` или настройки плагина в списке плагинов.
4. Отключите **старый режим получения сообщений** (`oldMsgGetMode`). Для выбранных лотов отключите стандартную автовыдачу Cardinal и другие плагины выдачи.
5. Нажмите **🔑 Подключение → ✏️ Ввести логин и пароль**. Используйте данные **GreenGamePay**, затем проверьте **💰 Баланс**.
6. Нажмите **📦 Мои лоты**, выберите лот и нажмите **➕ Настроить лот**. Бот предложит вид товара и по очереди запросит объём и лимиты. Проверьте сводку и нажмите **💾 Сохранить настройки**.
7. Нажмите **🟢 Включить автопокупку**. По умолчанию включён **тестовый режим**. После проверки сценария нажмите переключатель тестового режима и подтвердите переход к реальным покупкам.

### Обновление с прежних версий

Замените `plugins/greengamepay.py` новым файлом и перезапустите Cardinal. Откройте `/ggp`. Настройки, UUID плагина и журнал совместимы с прежними версиями — папку `storage/plugins/greengamepay` удалять не нужно. Существующие лоты остаются без паузы; старые значения объёма и лимитов не меняются.

GitHub-токен для работы плагина **не нужен**. Учётные данные GreenGamePay можно передать через переменные окружения `GGP_USERNAME` и `GGP_PASSWORD`: они имеют приоритет над локальным конфигом. Команда авторизации пытается удалить сообщение с паролем из Telegram; если удаление не удалось, удалите его вручную.

Команды и кнопки управления доступны только авторизованным администраторам Cardinal в личном чате с ботом. Плагин по умолчанию выключен, `dry_run=true`.

## Объём товара и лимиты

В меню **📦 Мои лоты** все параметры задаются по шагам. Числа можно вводить с точкой или запятой. Premium на 3/6/12 месяцев, валюты Steam и регионы подарков выбираются кнопками.

Пример: если ваш лот продаёт **50 Stars за одну единицу**, введите объём `50`. Покупателю двух единиц будет отправлено `100 Stars`. Если больше `500 Stars` в одном заказе отправлять нельзя, укажите максимум `500`. Затем задайте допустимую стоимость поставщика в **TON**.

Для Steam: если продаёте **пополнение на 100 ₽ за 110 ₽**, в плагине укажите **100 RUB**, а на FunPay цену **110 ₽**. При покупке двух штук покупатель получает **200 ₽** пополнения. Кнопка **🧮 Проверить расчёт** помогает проверить это без покупки; она не проверяет курс, баланс или наличие товара.

### Привязка командами — дополнительно

Старые команды остаются доступны. Следующие примеры нужны только для настройки через команды; обычная настройка выполняется кнопками.

Замените `12345` на ID своего лота. Примеры — шаблоны настроек, а не актуальные цены. Выберите лимиты под свой товар и баланс.

**Steam: 1 USD на единицу FunPay, до 10 USD за заказ:**

```text
/ggp_bind 12345 {"kind":"steam","quantity":"1","currency":"USD","max_quantity":"10","max_cost":"10"}
```

**Steam: 100 RUB за единицу, до 1000 RUB за заказ:**

```text
/ggp_bind 12345 {"kind":"steam","quantity":"100","currency":"RUB","max_quantity":"1000","max_cost":"15"}
```

**50 Stars за единицу, до 500 Stars; предел котировки 10 TON:**

```text
/ggp_bind 12345 {"kind":"stars","quantity":"50","max_quantity":"500","max_cost":"10"}
```

**Premium на 3 месяца, одна единица товара за заказ:**

```text
/ggp_bind 12345 {"kind":"premium","quantity":"3","max_quantity":"3","max_cost":"15"}
```

**Подарок Steam, регион KZ; замените SUB_ID на пакет нужной игры:**

```text
/ggp_bind 12345 {"kind":"gift","quantity":"1","sub_id":505826,"region":"KZ","max_quantity":"1","max_cost":"40"}
```

- `quantity` — объём товара **на одну единицу FunPay**, а не цена продажи. Покупка 3 единиц при `quantity=100` даёт 300. Итоговая цена FunPay не используется для вычисления пополнения.
- `max_quantity` — максимальный общий объём одного заказа в единицах `quantity`.
- `max_cost` — максимально допустимая стоимость: **USD** для Steam/gift, **TON** для Stars/Premium.
- Steam/gift: стоимость проверяется по ответу создания **до оплаты**. Если лимит превышен, у поставщика может остаться неоплаченный заказ.
- Stars/Premium: проверяется котировка до покупки. API не принимает `max_cost`, поэтому изменение курса и финальная комиссия могут увеличить списание. Это **не жёсткий серверный лимит**.
- Premium/gift принимают только одну единицу FunPay в одном заказе. Для Stars минимальное количество дополнительно проверяется у поставщика.
- Для `gift` доступны регионы `RU`, `UA`, `KZ`. **SUB_ID** — ID пакета Steam, не APP_ID.
- Каждый лот должен однозначно определяться названием, категорией, сервером и стороной. Неоднозначное совпадение останавливает обработку. Для простоты используйте уникальные названия лотов.
- Настройки сохраняются в заказе при его получении. Изменение или удаление привязки влияет только на новые заказы.
- Для паузы через JSON можно указать `"enabled": false` внутри привязки. Если поля нет, лот работает как раньше. Мастер сохраняет паузу при редактировании лота.

## Как покупатель получает товар

1. Оплачивает настроенный лот FunPay.
2. Получает запрос получателя, например `!ggp AB123 мой_логин`.
3. Получает сводку заказа и одноразовый код. Подтверждает командой `!ggp AB123 да a1b2c3` в течение 15 минут.
4. Плагин повторно проверяет оплату FunPay, обращается к GreenGamePay и сообщает о подтверждённой оплате поставщику.

Покупатель подтверждает заказ FunPay **после фактического получения**. Успешный ответ оплаты поставщика не равнозначен независимой проверке доставки. Плагин не подтверждает заказы FunPay и не делает автоматических возвратов.

При нескольких заказах в одном чате ID в команде исключает путаницу. Сообщения другого покупателя, администратора FunPay, бота или из другого чата не принимаются.

## Команды продавца

| Команда | Назначение |
| --- | --- |
| `/ggp` | Состояние и справка |
| `/ggp_auth ЛОГИН ПАРОЛЬ` | Сохранить учётные данные GreenGamePay |
| `/ggp_balance` | Проверить авторизацию, баланс USD и TON |
| `/ggp_services` | Каталог услуг поставщика (не все услуги каталога автоматизированы) |
| `/ggp_lots` / `/ggp_rules` | Лоты FunPay / сохранённые привязки |
| `/ggp_bind LOT_ID JSON` | Создать или изменить привязку |
| `/ggp_unbind LOT_ID` | Удалить привязку для новых заказов |
| `/ggp_on` / `/ggp_off` | Включить / остановить новые этапы покупки |
| `/ggp_dry on` / `/ggp_dry off` | Тестовый / реальный режим |
| `/ggp_orders` | Последние 20 заказов |
| `/ggp_order ORDER_ID` | Подробности, состояние, custom_id и ошибка |
| `/ggp_resume ORDER_ID` | Повторить только `blocked`/`ready`: создание и оплата ещё не отправлялись |
| `/ggp_redeliver ORDER_ID` | Повторить сообщение о подтверждённой оплате, без повторной покупки |
| `/ggp_resolve ORDER_ID done` | Отметить завершённым после ручной проверки |
| `/ggp_resolve ORDER_ID cancelled` | Закрыть запись после ручной проверки; это не возврат средств |

`/ggp_off` останавливает следующие этапы. Уже отправленный HTTP-запрос отменить нельзя. Отключение плагина в Cardinal также проверяется перед оплатой.

## Ошибки и перезапуски

| Состояние | Действие |
| --- | --- |
| `waiting` / `confirm` | Ожидание получателя / подтверждения; сохраняется после перезапуска |
| `ready` / `blocked` | Покупка ещё не отправлялась. Исправьте причину и используйте `/ggp_resume` |
| `creating` / `paying` | Запрос в процессе. После аварийного перезапуска переводится в `review` |
| `created` / `review` | Нужна ручная проверка у поставщика по `custom_id`; автоматического повтора нет |
| `paid` | Оплата подтверждена, сообщение не доставлено. Используйте `/ggp_redeliver` |
| `done` | Сообщение отправлено либо запись закрыта продавцом |
| `dry_run` | Тест без API-покупки; автоматически не превращается в реальную покупку |
| `cancelled` | Обработка закрыта; возврат денег этой отметкой не выполняется |

После таймаута оплаты сначала проверьте списание и получение товара у поставщика. Для Stars/Premium сервер не принимает идентификатор идемпотентности; повтор может привести к повторному списанию. В этом плагине нет команды повторной оплаты для `review`.

Новые заказы, пропущенные во время выключенного Cardinal, автоматически не закупаются при запуске. Обработайте их вручную. Тестовые `ADTEST`-события Cardinal игнорируются: тестовый сценарий плагина требует настоящего оплаченного заказа и включённого `dry_run`.

## Хранение и ограничения

Данные находятся относительно рабочей папки Cardinal:

```text
storage/plugins/greengamepay/
  config.json     # учётные данные и настройки
  orders.db       # журнал заказов и запреты включения снятых лотов
  instance.lock   # блокировка второго процесса
```

Не удаляйте журнал между перезапусками: он защищает от повторной покупки. Резервную копию делайте при остановленном Cardinal и храните приватно: она содержит персональные данные и может содержать пароль. Файлы не входят в репозиторий; на POSIX устанавливаются права `0600`. На Windows доступ регулируется ACL папки.

Один аккаунт FunPay должен обрабатываться одним экземпляром плагина. Блокировка защищает только процессы, использующие одну папку хранения. Работа через несколько машин/копий хранилища не поддерживается.

Подарочные **коды/карты** из общего каталога не автоматизированы: опубликованный контракт `/pay_order` не описывает получение кодов. PaymentHub/эквайринг также не используется: оплата покупателя уже проходит через FunPay. Плагин не меняет цены. Снятие лотов с продажи выполняется только при включённом контроле баланса в реальном режиме.

## Разработка и проверка

```bash
python -m pip install -r requirements-dev.txt
python -m pytest -q
python -m ruff check .
python -m compileall -q greengamepay.py
```

Тесты не обращаются к внешним API и не списывают средства. Для дополнительной проверки реального загрузчика Cardinal задайте `CARDINAL_SOURCE` на путь к его checkout и выполните `python tools/check_cardinal_loader.py` из окружения с зависимостями Cardinal.
